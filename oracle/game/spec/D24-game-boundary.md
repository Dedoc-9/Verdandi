# D24 — The game-layer boundary contract (what is canonical, and what is only a view of it)

Status: **DECLARED — a boundary, not a subsystem.** No game module existed at the commit that wrote
this. D24 draws the line the *first* game module will be held to, before there is one to hold, for
the same reason `voxpath` registered its predictions one commit before its arms existed: a line
drawn after the code is a description of the code, and a line drawn before it is a contract. Its
correctness test is **retro-admission**, D17's shape — when the first game-layer module lands it
must classify cleanly under §1, or D24 is wrong and is amended *before* the module is graded.
**Discharged once** (§9): the first module classified without amendment.

The target is an action RPG in the shape of *FATE* (WildTangent, 2005): real-time combat in a fully
3D dungeon of randomized levels, depth bounded at 2 147 483 647, a companion animal that fights,
carries, sells in town and transforms by eating fish, a fishing economy, classless progression, and
retirement into a descendant who inherits a family heirloom that gains a quarter more enchantment
each generation. Those mechanics are the *worked examples* below, not the contract; the contract is
the one question every subsystem must answer.

## 1. The one question

> **Does this affect canonical game state, or is it a view of canonical game state?**

Every new module answers it before it is written, and the answer decides which regime it enters.
There is no third answer. A module that does both is two modules.

This is D15's view contract and the four-layer discipline (`CORE` / `VIEW` / `ALLOCATOR` /
`OBSERVER`) applied to a domain where the temptation to blur them is strongest, because in a game
the view is the product and the state is invisible. The cardinal invariant does not move: **replay
stays byte-identical with every observer active**, and a particle effect, a camera, a sound, a
health bar, a damage number floating off a monster — none of these may touch what replay reads.

## 2. Canonical game state

Declared as a *shape*; the exact field set is bound by the first module that constructs it and is
graded then, not here.

    seed                      the run's generative root, exact integer
    world identity            content-addressed, the way `worldbind` names a chunk by its digest
    generated dungeon state   every level that has been generated, by seed and depth
    entity state              player, companion, monsters, town population — position, health,
                              inventory, equipment, progression, transformation
    RNG state                 the deterministic stream, advanced only by canonical actions
    authoritative action history
                              the ordered inputs replay consumes — `lockstep.canon` inherited,
                              not restated

What is **not** canonical, by construction: the camera, the frame, the audio, the UI, any
interpolated position between ticks, any cosmetic roll that does not feed back into state. The test
is D15's: change it, and the carried witness must not move.

## 3. What enters the verification regime

These have mechanically falsifiable authority claims and get the existing treatment — REGISTER
where a prediction is made, construct, falsify red-first, measure, discharge or retain the debt.

| subsystem | the authority claim | the falsifier shape |
|---|---|---|
| dungeon generation | seed → canonical structure → digest, same seed same bytes any host | `heightfield`'s corpus law, applied to a level: a pinned digest per (seed, depth), and a mutated generator diverges |
| generation invariance | the structure is a function of the seed alone | `voxin`'s permutation law: iteration order, dict order and traversal order move not one bit |
| topology | the stairs down are reachable from the stairs up; no sealed region; declared room count | a reachability witness per level, and a planted wall that seals a room reddens |
| depth representation | the bound is 2 147 483 647 because that is what a signed 32-bit integer holds | **derived, not chosen** — the way `voxlat` derived `coord_bits <= 20` — and enforced at a door that refuses depth one past it; and the open question the original never asked: *does the deepest level actually generate, or does something overflow first?* Either answer is a result |
| loot generation | seed + level + source → deterministic drop | pinned corpus where an independent expected result exists; the RNG advances only on canonical actions |
| combat arithmetic | damage, mitigation and hit resolution obey the declared formula exactly | the formula is data, the resolution is checked against it, and a planted off-by-one reddens |
| persistence | a run serializes, restores and re-binds bit-identically | `persist` / `testament` / `resurrect` inherited; a truncated or tampered save refuses typed |
| heirloom progression | a quantity that grows by a declared fraction each generation | declared **direction and baseline**, `ratchet`'s shape — the quantity is data and the direction is enforced, not promised |
| replay / lockstep | the existing machinery over the new state | `lockstep.canon` imported; two peers assembling the same action union in different orders produce the same run |

## 4. What does not get a counterfeit oracle

These matter as much as anything in §3 and have **no ground truth**. They ship graded `DECLARED`
with design constraints and measurements, and never with a falsifier pretending to be a proof.

- monster behaviour and companion behaviour
- combat balance, difficulty, progression pacing
- drop-rate *feel*, companion *usefulness*
- whether a build is fun, whether a generated level is interesting

The distinction is sharpest in combat, and it is a distinction of *sentence*, not of subject:

> gateable — *damage calculation is deterministic and obeys the declared formula.*
> not gateable — *this combat system is balanced.*

The second sentence becomes gateable on exactly one condition: an independently defensible oracle
for "balanced" is defined first, registered, and falsifiable. Until then a row asserting it is a
row that cannot fail. A measurement such as "testers preferred the second curve" is admissible as a
**measurement** — a named cohort, a named protocol, a committed record — and is never interchangeable
with a law.

The worked examples, classified:

- **the companion.** Its inventory, position, health, current transformation and the fact of a
  sale are canonical state (§3). What it *chooses* to attack is behaviour (§4). Its transformation
  rule — *this fish yields this form, permanent until another fish* — is a declared table and is
  gateable as data.
- **fishing.** The catch is a canonical draw from the RNG stream (§3). Whether fishing is worth a
  player's time is §4.
- **retirement.** The descendant's bonuses and the heirloom's growth are canonical and ratcheted
  (§3). Whether the grind to retirement is well paced is §4.

## 5. The renderer is the hard boundary

FATE is real-time and fully 3D, and this tree has already measured what that costs.

`voxwork-clock` places wall-clock **off-gate by rule**: a timing assertion inside a deterministic
gate is nondeterministic, flakes, and is then loosened until it cannot fail. `voxref` is
deliberately naive — every face of every solid voxel, buried ones included, no culling of any kind.
`voxbreak` measured **every certificate admission rule underwater** against the committed
reference, the tiled loop itself costing more than three times everything the certificate retires.
`sealframe` puts the *evidenced* share of the presentation budget at one segment of seven.

So "does it hold a frame rate" is the first performance question the game layer inherits, and it
arrives carrying a negative result. D24 does not answer it and does not turn it into a frame-time
gate. It preserves the split:

    DETERMINISTIC CORRECTNESS            on-gate, counts, byte-identical
        generator · world state · entities · combat arithmetic · persistence · replay
                     |
                     v
              canonical game state
                     |
                     v
    VIEW / RENDER
        correctness properties           on-gate — D15: presentation is observational only
        performance                      off-gate — MEASURED on a named host, in a committed
                                         record, under `sealframe`'s door, never a gate row

A renderer that is fast and wrong is a defect. A renderer that is correct and slow is a
measurement. Only the first is a gate's business.

## 6. Dependencies: the view may have needs, the core may not

The game layer is permitted what the verification substrate is not: **declared dependencies in
service of presentation quality** — a real rendering backend, audio, input, a windowing system.
Under three conditions, each of which is the existing rule restated rather than a new one:

1. **The core stays as it is.** Canonical state, the generator, combat arithmetic, persistence and
   replay import nothing the gate does not already run on. If a game-layer module that touches
   canonical state needs a dependency the gate lacks, the module is on the wrong side of §1.
2. **A view dependency is declared, and its absence is a labelled SKIP.** `voxin-placement` records
   `SKIPPED (rustc absent) — honestly labelled, not passed` on a host without a compiler. A view
   backend that is absent records the same shape. A view dependency that is *required* for the gate
   to be green has become a core dependency, which is a §1 violation caught by the gate going red
   on a host without it.
3. **A view dependency never enters a digest.** The frame digest law (D11 §4) is over the bytes the
   view *derives from* canonical state, never over what a backend produced from them.

## 7. The first vertical slice is the generator

Because it has the cleanest correspondence to machinery already proven here — `heightfield` for
the seeded canon, `voxin` for the invariance law, `worldbind` for content-addressed identity,
`voxlat` for a derived rather than chosen bound — and because it is the one place where the game
layer can be shown to enter the authority discipline *without importing false certainty*: a level
either reproduces its digest or it does not, and nobody has to say whether it is fun.

The generator is a rung, with a brief, a corpus, red-first falsifiers, and a `does_not_show` that
says in its first clause that a level which reproduces is not a level worth playing.

## 8. Grade

**DECLARED.** This document asserts a partition and a procedure and measures nothing, because
there is nothing yet to measure. Its falsifier is retro-admission (the status note above): the first game-layer module
either classifies under §1 or this contract is amended first. Its `does_not_show`: that the game
will be built; that the substrate can render it at any frame rate — §5 says the opposite is the
current measurement; that §3's table is complete, it being the subsystems FATE's mechanics
*visibly* require and not a design; that the §4 list is exhaustive, only that everything on it lacks
an oracle today; and nothing about what the game should *be* — D24 decides where a claim may
stand, never what to build.

`gamegen` is §7's generator and supplies exactly one field of §2's shape (generated dungeon state,
for one level). It claims nothing from §3 beyond generation and invariance. `descent` is §3's
topology row: it reads a `gamegen` level and witnesses that the stairs down are reachable from the
stairs up with a concrete path, and a planted sealed room reddens — the two directions §3 named. It
consumes `gamegen` and adds no claim `gamegen` makes; the sealed room is where generation-correctness
and traversability visibly come apart, which is the two-oracle discipline of §4 holding one layer
down. Neither claims anything from §4's un-oracled list. `move` is the first authoritative transition: it puts an entity on a level and steps it one cell, producing the `D_n → D_{n+1}` that §5's renderer boundary — KINEMA (D25) — will one day refine. It establishes that a wall step is a legal BLOCKED outcome (`D_{n+1} = D_n`), the authoritative pair D25's Plant A consumes, rather than a typed refusal, and it single-sources movement legality in `descent.traversable`, promoted to public here so authority is consumed and never reinvented. `entity` supplies §2's entity-state field as a **content-addressed component**: `move` had inlined the entity's position into its state identity, and this rung makes the entity a record named by its own digest, so `move` names it the way it names the level and there is one identity vocabulary through to §2's assembled snapshot — no second serialization for `statecanon` to reconcile. Only position is earned, so the record carries exactly that field and refuses any other, which is how §2's "not canonical" view quantities (a facing for animation, an interpolated position) are kept out of the digest by construction rather than by convention. `rngstream` supplies §2's **RNG state** as the first *stateful* canonical component: where `gamegen` draws statelessly, the stream's advancing is itself a canonical state change, so its digest enters canonical identity. It roots at the run's `seed` (§2's generative root) through a domain-separated root, carries an explicit `(n, R_n)` index, and is advanced only by canonical actions — a read cannot advance it, by construction — with `move` measured to leave it a fixed point, so the "advanced only by canonical actions" clause is enforced rather than asserted. `descend` is the first authoritative transition that changes **depth**: from the down-stairs of the level at depth *d* it produces the level at *d+1* from the same seed, the entity arriving at that level's stairs-up. It consumes the depth authority (`gamegen.check_params`, asked before any generation, so the ceiling refusal at `DEPTH_MAX` is `gamegen`'s and no second depth law is minted), the successor generator (`gamegen.generate`) and the stair locators (`descent.endpoints`), and it touches no RNG — the successor is fully determined by seed and depth, so a descent consumes no draw. Its one new refusal is narrow: descending from anywhere but the unique down-stairs. `loot` is the first authoritative action that **consumes** the RNG: from a canonical source `(level, pos)` and the current stream `R_n` it derives a uniform selection over a frozen table by a `peek` of `R_n`, and a single `advance` folding the source produces `R_{n+1}` — the transition `(source, R_n) → (drop, R_{n+1})`, not `seed → drop`, because the stream is stateful and the seed enters only through `R_0`. It answers §2's implicit question of *which* actions advance the stream with a first concrete instance, owns that advance itself (so a later `actionlog` records rather than performs it), changes no state but the RNG (there is no inventory field yet, so the drop is a generated result), and requires no traversability of the source — a wall is a valid `(level, pos)`, because source identity is not gameplay eligibility. `combat` is §3's **combat arithmetic** row, and the first game-layer rung that is a certified arithmetic law rather than a state transition: `resolve(attack, defense) = max(0, attack − defense)` over a declared byte domain, the smallest law that still mitigates. It is exactly §3's gateable sentence — "damage calculation is deterministic and obeys the declared formula" — and refuses §4's un-oracled "combat is balanced": the resolution is checked against a *neutral ruler* (an independent `min`-oracle over the whole domain and a corpus of frozen literal tuples, not the formula checking itself), and a planted off-by-one reddens. The transition fork was settled toward a **derived result**, not `(attacker, defender) → (attacker′, defender′)`: `entity.FIELDS` is position-only and the construction chain `entity.at(pos) → entity.digest_at(pos) → move.state_bytes` means persistent health would *break* `move`, so health is a new canonical-state contract deferred to the rung that needs persistence, and combat generates a damage integer the way `loot` generated a drop with no inventory. It is deterministic — the smallest law needs no randomness, so it takes no `rngstream` edge and remains a stdlib leaf — and earns no result representation yet, the conformance corpus being the identity. `heirloom` is §3's **heirloom progression** row, and the second certified arithmetic law: an inherited quantity grows by a declared fraction each generation, `heir(q) = q + (q · NUM) // DEN` with `NUM/DEN = 1/8`, monotone non-decreasing. It is §3's gateable sentence — "the growth is deterministic and obeys the declared fraction" — and refuses §4's "the progression is rewarding or balanced": the growth is checked against neutral rulers (an independent combined-numerator oracle and a floor-free count-of-multiples oracle over the whole corpus, plus frozen literal tuples), the direction is enforced (never shrinks; strictly positive above the floor threshold `q ≥ DEN/NUM` and exactly zero below it, the honest floor semantics), and a planted shrink or off-by-one reddens. Like `combat`, the transition fork was settled toward a **derived quantity** rather than a persistent state: the measurement found no game-layer persistence substrate (the `persist` rung is unbuilt, and the existing `persist.py`/URDRLAT5 is a different arc), `entity` is position-only and a progression field would break `move`, and the direction-and-baseline authority operates on source constants across git history — so making a container inside `heirloom` would be architectural invention, and the quantity is a declared input whose generations are a computed sequence, not stored state. It imports nothing under `tools/` — a stdlib leaf, its predicted `entity`/direction-register dependencies superseded by measurement. `actionlog` is §2's **authoritative action history**, the first sequence/order rung and the first consumer since `loot`. `rngstream` already commits to the ordered history through its one-way chain but DISCARDS the actions; `actionlog` owns the one thing the stream lacks — RECOVERABILITY — so `replay` can re-consume them. Its order-committing identity IS `rngstream`'s fold from a declared seed-independent root (`append` is exactly one `rngstream.advance`, and it builds no second hash chain), and its tokens are canonicalized by `rngstream`'s own rule, so there is one ordering authority and one action vocabulary. The stream-agreement law is the external ruler: folding the logged actions through a run seed reproduces that run's stream and a reordered log diverges it, so order is certified by an authority `actionlog` does not own rather than by agreeing with its own digest — a recoverable SOURCE SEQUENCE that reproduces a stream, not a claim to be the unique preimage of one. The tokens stay opaque because no canonical action vocabulary has been earned (a move command does not even advance the stream), so it imports no `move` or `entity`; a typed vocabulary, the "replay consumes only this" claim, disk persistence and entity binding are deferred to `replay`/`persist`/`statecanon`. `savegame` is §3's **persistence** row (chain role "persist"): the durable, content-addressed serialization of the earned canonical components — `seed`, `depth`, entity `pos`, the RNG stream `(n, R_n)`, and the actionlog entries — each serialized independently, length-framed, and reconstructed **directly** on restore (the level regenerated from `(seed, depth)`, the entity from `pos`, the stream from `(n, R_n)`, the log from its entries), each verified against its own identity authority. It gets its own module and glyph because `persist.py`/URDRLAT5 is the MMO rollback-window arc bound to `storecost`/`horizon` and is not reusable as a game-state API; only the tree's `SHA(MAGIC|content)` content-addressing vocabulary is reused, which is broader than that module. Crucially, **persist stores canonical state while replay derives it**: because the actionlog records opaque tokens (including actions that do not advance the stream), folding it does not reproduce the RNG state, so restoration reconstructs each component directly rather than replaying — re-derivation from the action history is `replay`'s rung, not this one's. The record is a durable serialization of the earned components, **not** the assembled canonical `D_n`, which `statecanon` earns later; disk I/O, multi-entity rosters and manifests/windows are deferred, and every flip, truncation, reorder and validly-re-sealed-but-wrong-component refuses typed. `enact` is the **typed action authority** (§2's action vocabulary, the prerequisite `replay` was missing): it gives each recorded action a KIND and a PAYLOAD and binds it to the one transition that owns it. The kinds are EXACTLY the three canonical state transitions found by code sweep — MOVE→`move.step`, DESCEND→`descend.descend`, LOOT→`loot.loot` — and `combat`/`heirloom` are excluded as pure derivations (they take declared integers and return a number, holding no canonical component), because including them would manufacture a state authority rather than discover one. Dispatch binds and reimplements nothing (the routed result equals the authority called directly), RNG attaches by kind (only LOOT advances the stream, so a recorded action is not a draw), and ordering is `actionlog`'s append order — cross-peer canonical ordering is `lockstep.canon`'s, whose `(tick, peer, seq)` key game actions do not carry, so it stays `replay`'s. The neutral ruler is `savegame`, which stored the components independently of any dispatch: the actionlog→decode→dispatch chain reproduces exactly what it stored, and a corrupted token diverges it. Single-peer; from-origin replay, cross-peer reconciliation, the assembled `D_n` and health/inventory binding are deferred. `replay` is §3's **replay** rung and a certification layer, not a new authority: from a saved run it reconstructs the origin from earned state (seed, `savegame.depth − DESCEND count` — depth moves only via descend, so origin depth is recoverable without a new record, closing Slice B — then `move.spawn` and `rngstream.root`), folds the recovered history through `enact`, and certifies the fold reproduces the state `savegame` stored **independently**. The origin is reconstructed and then verified, never trusted: depth equality is tautological (depth0 is derived from the stored depth), so the discriminator is the mutable `(pos, stream)`. The verdict is REPRODUCED or DIVERGED — a return, not a refusal — and because `savegame` stores the log and the state independently, an inconsistent pair restores fine and replay is the law that catches it. It adds no transition or RNG authority (the fold is `enact.apply`), and it is single-peer: cross-peer union via `lockstep.canon` needs `(tick, peer, seq)` game actions do not carry (Slice A), deferred with the assembled `D_n` (statecanon) and observers (KINEMA). `statecanon` is §2's **assembled-state** rung, and it is deliberately the smallest one that closes the section: every prior rung earned an identity for one component of a run — `gamegen.level_digest` for the world, `entity.entity_digest` for the entity, `rngstream.stream_digest` for the RNG, `actionlog.digest` for the ordered history — so the assembled canonical identity is not a new mechanism but a **composition**, `D_n = SHA-256(MAGIC | lvl | ent | rng | log)`, minting exactly one new digest over the four already-earned ones and reimplementing none of them. The single substantive choice — whether §2's canonical state is the current world alone or the run-and-how-it-arrived — is settled toward the latter: the action history enters `D_n` through `actionlog.digest`, so two runs at the same `(level, entity, stream)` reached by different histories have different identities, and no separate seed field is added because `gamegen.level_digest` already commits to seed and depth. The authority/view boundary §2 draws by hand — a facing or an interpolated position is *not* canonical — holds here by construction, because such a quantity cannot enter `entity` and so cannot reach `D_n`; and the three §2/§3 persistence laws stay disjoint, `savegame` asking whether a state can be restored, `rerun` whether a history reproduces it, and `statecanon` what its canonical identity is, none absorbing another. The gate enforces the composition structurally, not merely by output: a mutant that reproduced `D_n` while bypassing one of the four authorities reddens on the module's own AST.
